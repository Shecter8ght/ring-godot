# Сюжетные квесты

Система — `src/quests/`, данные — `data/quests/`. Первый реализованный квест — «Не вернулся»
(`data/quests/missing_anton.json`). Торговые задания Михалыча (`Missions`, `data/missions.json`)
— отдельная, более простая система; сюжет её не заменяет.

## Требование к кампании и обучению — 2 октября 2026

Все миссии и обучение должны проходиться одним, двумя или тремя игроками. В активной группе
одинаковое задание и один прогресс: действие любого участника автоматически засчитывается
всем. Один вынесенный предмет или спасённый NPC закрывает общий заказ; личная гибель другого
участника не отменяет общий зачёт. Снаряжение, здоровье и потери остаются личными.

Обязательные действия выполняются последовательно одним человеком. Распределение ролей
ускоряет работу, но миссия не требует одновременного присутствия двух или трёх исполнителей.
Подсказки управления остаются личными и не требуют повторять действие вслед за напарником.
Это правило применяется и к сюжетным квестам, и к торговым поручениям `Missions`.

Общий сюжетный прогресс уже реализован в Quests (коммит 37d45d1), см. раздел о группе ниже.
Торговые Missions остаются личными. Предлагаемые новые эпизоды, ранние факты,
именные грузы и их общая приёмка ещё требуют реализации после оценки
[главы 1](chapter_1.md); одного нового JSON с целями недостаточно.

## Устройство

| Слой | Где | Что |
|---|---|---|
| Данные | `data/quests/<id>.json`, список — `index.json` | этапы, цели, диалоги, места в мире, награда, флаги |
| Состояние | `Profile.quests`, `Profile.flags`, `Profile.unlocked_stock`; у гостя — `Profile.guest_campaigns` | кампания хоста сохраняется у участников; собственная кампания гостя остаётся отдельной |
| Логика | `quest_manager.gd` (autoload `Quests`) | состояния, события → цели, рейд (копия до эвакуации), награды, отладка |
| Мир | `quest_world.gd` (создают Raid и HideoutLevel), `quest_site.gd`, `quest_props.gd`, `quest_anchor.gd` | места квестов на уровне, заглушки сцен, осмотр/обыск/зона, раненый NPC на плече, охрана этапа |
| Интерфейс | `quest_hud.gd` (внутри `Quests`) | цель справа сверху, сообщения, реплики, разговор, журнал (J), консоль разработчика (`) |

### Состояния
- Квест: `LOCKED` (не выполнено `requires`) → `AVAILABLE` → `ACTIVE` → `COMPLETED` / `FAILED`.
- Текущая цель (`Quests.status`): `OBJECTIVE` → `WAITING_FOR_EXTRACTION` (найдено — уйти живым)
  → `RETURN_TO_NPC` (поговорить).

### Рейд
Сделанное в рейде сначала хранится в копии у хоста. Если хоть один участник эвакуировался,
подтверждённые результаты фиксируются для группы; последующие изменения этого рейда
тоже сохраняются. Если не вышел никто, незавершённая попытка не засчитывается.
Гибель одного участника не отменяет общий результат остальных.
Цель выноса предмета или NPC всё равно требует эвакуации именно с этим грузом.

### Цели (`objectives[].type`) и события мира
| Тип | Засчитывает событие |
|---|---|
| `talk` (npc, dialogue) | разговор в убежище дочитан |
| `interact`, `find_clue` (site) | F у места (find_clue ещё кладёт улику в журнал: `clue`) |
| `search_location` (site) | обыск: `search_s` секунд рядом |
| `enter_zone` (site) | вошёл в радиус `zone` |
| `pickup_item` (item) | предмет в рюкзаке |
| `reach_extraction`, `survive` | эвакуация |
| `extract_with_item` (item) | эвакуация с предметом в рюкзаке |
| `extract_with_npc` (npc) | эвакуация, неся NPC (или он в 5 м) |
| `kill_targets` (n, arch) | добил мародёров (тип — по желанию) |
| `photo` (site) | снимок в точке съёмки: F, кадр видоискателя (место с `photo: true`) |
| `clear_site` (site) | мертвы все бойцы охраны этого места (`guards` этапа), остальные не в счёт |
| `install`, `deliver` (site, item) | груз из рюкзака у места — засчитан **сразу и без эвакуации** (`durable`, в профиль) |
| `take`, `put` (site, item) | убежище, обучение: взять предмет себе / положить из своего рюкзака |
| `ui` (what: inventory / terminal) | открыл окно; открыл раньше подсказки — засчитано заранее |

Поля цели: `text`, `hint`, `clue {title, text}`, `toast`, `set_flags {…}`; `reward {…}` — оплата этапа
(каждому профилю один раз); `variants [{facts, flags, dialogue, set_flags}]` — другой разговор, если
игрок уже знает больше; `skip_if_facts […]` / `skip_if_flags {…}` — шаг не нужен (засчитан сам);
`button` — надпись кнопки в терминале; `log […]` — сообщение в переписку по выполнении;
`test_hint` — инструкция для тестового прохождения (при `Balance.QUEST_TEST_HINTS`).

**Факты и ранние находки.** Осмотренные / снятые места — факты квеста (`facts`). Место с `early`
(true — с принятия заказа, «id этапа» — с этого этапа) работает раньше своего этапа; цель, чьё место уже
в фактах, засчитывается сама, как только станет текущей. Пропущенная цель фактом не становится.
Поля этапа: `title`, `objectives`, `guards {site, n, radius}` — мародёры держатся у места.
Поля квеста: `title`, `giver` (кто даёт: `trader`), `summary`, `offer`, `requires {trust_level,
flags, quests, scenes, after}`, `reward {money, trust, items, unlock_stock}`, `flags_on_complete`, `dialogues`,
`sites`; `via: "terminal"` + `contacts {id: {nick, name, role, color}}` — заказ по переписке (ниже);
`auto_start` — начинается сам (обучение). `requires.scenes` — пока сцены нет, задание не предлагается;
`requires.after` — после другого (выполнен или вовсе не начинался).

**Переписка в терминале** (`via: "terminal"`): заказчик и его люди пишут в терминал убежища (раздел
«Переписка»), видимых NPC нет. Разговоры — обычные цели `talk` с `npc` из `contacts` (или заказчик
`Contracts`, например `perevalka`); принять заказ и отправить отчёт — кнопками окна, входящее до ответа
игрока видно сразу; история — в записи квеста (`log`). Окно — `src/hideout/terminal_ui.gd`.

### Места (`sites`)
- `level` — сцена (`f1_ring`, `hideout`).
- `anchor` — где: `polar [угол, радиус]` (кольцо), `node + local` (относительно узла уровня —
  например `Buildings/GarageA`), `near + offset` (рядом с другим местом), `pos`. **Узел
  `QuestAnchor` с тем же `site_id` в сцене уровня главнее** — поставил мышкой, место переехало.
- `props` — заглушки: `backpack, blood, drops, casings, butts, crate, chair, note, papers, tarp,
  ammo_taped, cabinet, bundle, red_gate, cot, item (id)`.
- `prompt` + `lines` — осмотр; `search_s`; `zone`; `npc` (раненый: несут на плече); `photo` — точка
  съёмки; `early` — раннее место; `supply` — источник груза (выдаёт деталь, пока заказ её ждёт; один
  экземпляр с места за раз); `cargo` / `placed` — модель предмета лежит / появляется (у места-источника
  `cargo` лежит, пока заказ деталь ждёт и пока её никто не несёт; у места сдачи install / deliver
  `placed` — когда всё, что место ждёт, сдано, и в следующих рейдах тоже); `no_floor` —
  точно в точке, без поиска пола;
  `when_flags` — место есть всегда, когда флаги совпали (Антон в убежище).
- На уровне стоят все места текущего этапа (сцена рассказывает историю), осмотреть можно только
  место текущей цели.

### Реплики
- Диалоги (`dialogues`): `[кто, текст]`; `кто = "player"` — герой (подпись «Я», голубой цвет).
- `lines` мест, `say` / `say_start` целей: строка — описание (что видишь, светлым), `[кто, текст]`
  — реплика (герой — голубым, NPC — янтарным). `say` — цель выполнена, `say_start` — цель стала
  текущей. Герой должен говорить: на находку, на вход в новое место, в ответ собеседнику.

## Новый квест
1. `data/quests/<id>.json` по образцу `missing_anton.json`, строка в `index.json`.
2. Места — `anchor` в данных или `QuestAnchor` в сцене.
3. Проверка: консоль разработчика (`), `tools/quest_test` как пример прогона.

Код трогать нужно только для нового **типа** цели или события.

## Группа (кооп на 1–3) — общий сюжет

Реализовано по `new_game_intro.md` §11 (2026-10-02):

- Одно состояние сюжета на группу — у хоста (`Quests`); соло — группа из одного. Хост рассылает
  снимок всем после каждого изменения и при входе/смене сцены участника (подключившийся позже
  получает текущее).
- Клиент ничего не засчитывает сам: осмотр / обыск / зона места, разговор с Сергеем, поднять и
  положить раненого — просьбы хосту (`Quests.request_site`, `finish_talk`, `request_carry`). Хост
  сверяет: место есть, просящий рядом (`QuestWorld.near_site`), цель текущая.
- Убийства («убить N»), «предмет в рюкзаке» и эвакуацию хост считает сам за любого участника.
- Места и раненые NPC общие: у всех одни и те же; раненого несёт тот, кто поднял, — видно всем;
  упал или ушёл несущий — раненый остаётся там.
- Зачёт: сделанное в рейде засчитывается всем, если хоть один из группы эвакуировался (с этого
  момента и до конца рейда — сразу); не вынес никто — попытка не в счёт.
- Награда за квест — один раз на профиль (отметка `rewarded`; у гостя — список в его копии
  кампании). Группа идёт по кампании хоста: гость хранит её отдельно (`Profile.guest_campaigns`),
  своя кампания не трогается.
- Проверка: `tools/coop_quest_host` + `coop_quest_client` (две копии игры по сети).
- Ещё не общие: торговые задания Михалыча (`Missions`) — следующим шагом.

## Тестовые инструкции

`Balance.QUEST_TEST_HINTS` (сейчас `true`, владелец 2026-10-17): у целей с `test_hint` при смене цели
слева всплывает рамка «ТЕСТ — что делать» (`QUEST_TEST_HINT_SEC`), та же строка — в журнале (J) и
внизу переписки в терминале. К релизу — `false`; тексты в данных можно оставить или удалить.

## Отладка
Консоль (`) — только при запуске из проекта (в `RING.zip` её нет):
`quest start missing_anton`, `quest stage missing_anton 3`, `quest completeObjective`,
`quest reset missing_anton`, `quest list`. Команды пишут сразу в профиль.

## Что временно
- Заглушки сцен — простые меши (замена: модели через `ModelProp` / сцены в `props`).
- Раненый NPC — фигура из коробок; «на плече» — та же фигура; анимаций нет.
- Разговоры — текстом внизу экрана, без выбора реплик (герой отвечает, но ответ один).
- Антон в убежище — лежит на койке, говорит две фразы.
