# Оружие, патроны, обвес, броня — архитектура

Фаза 1 задачи «расширить вооружение»: что было в проекте, что переиспользуем, как встраиваем.
Ниже — решения, которые сохраняются в коде; если код расходится с этим файлом — правим файл.

## 1. Что было

| Система | Где | Как устроено |
|---|---|---|
| Справочник предметов | `data/items.json`, `ItemDb` | Предмет — словарь `{id, n}` + состояние (`dur` у брони, `mods` у оружия), позиция в сетке `x, y, r`. Категории `cat`, размер `size`, цена `value`, стопка `stack`. |
| Оружие | `Balance.WEAPONS` (4 ключа: pistol / rifle / shotgun / bolt), предметы `w_*` с `equip.weapon` | Урон, темп, магазин, разброс, отдача — в балансе по ключу. Один патрон на калибр (`ammo_9x19`, `ammo_545`, `ammo_12`, `ammo_762r`). |
| Обвес | `items.json → mod`, `WeaponMods`, `WeaponStats` | Слоты optic / muzzle / grip / stock / mag / tac / bipod, совместимость — список оружия (`fits`). Позиции крепления — в коде (`WeaponMods.MOUNTS`). Эффект — множители `fx`. Один tac-слот. |
| Модели | `WeaponModels` | Процедурные: пистолет, АК, помпа, болтовка. Meta: `muzzle`, `sight_h`, `ads_z`, `ocular`. Внешних моделей оружия нет. |
| Стрельба | `Player._fire` → `Hitscan.fire` | Луч, разброс; урон `Health.apply_or_request_damage(amount, from, zone, attacker)`, считает хост. Зоны: head / body / blast. |
| Броня | `Inventory.absorb` | «Доля снятого урона» + прочность (≈ доп. HP). Шлем защищает голову от ваншота. |
| Патроны у игрока | `Player.ammo`, `ammo_by`; `Raid.request_consume` | Магазин — число; перезарядка берёт патроны из рюкзака (хост вычитает). При эвакуации патроны из магазинов возвращаются. |
| ИИ | `Balance.AI_WEAPONS`, `Marauder` | Свой упрощённый ствол, бесконечные перезарядки; при смерти — ствол + случайный запас патронов + таблица лута. Броня — множитель урона. |
| Лут, торговец | `data/loot.json`, `data/trader.json` | Таблицы `[id, вес, [мин, макс]]`, бросков `rolls`; торговец — список id + уровень доверия. |
| Сохранение | `Profile` (json) | stash / equipment / backpack / pocket — списки тех же словарей-экземпляров. |
| UI | `InventoryUI` (рейд), `HideoutUI` (верстак), `GridView` | Сетка, контекстное меню, верстак: список слотов обвеса. |
| Ввод | `project.godot` actions | fire, aim, reload, flashlight (T) и т.д. |

## 2. Что переиспользуем

- **Экземпляр предмета = словарь в инвентаре.** Definition — в данных, Instance — сама запись
  (`dur`, `mods`, `mag`, `sight`…). Сетка, перенос, сохранение, репликация уже работают со словарями.
- **ItemDb** остаётся единым реестром предметов; оружие/патроны/магазины/обвес/броня — в своих
  файлах данных, ItemDb подмешивает их в общий справочник (имя, размер, цена, вес, теги).
- **WeaponStats** — единственное место расчёта характеристик (теперь от экземпляра + патрона).
- **WeaponModels / WeaponMods** — процедурные модели и детали обвеса остаются запасным вариантом;
  точки крепления переезжают в данные.
- **Hitscan → Health (хост)** — та же цепочка, к урону добавляются параметры пули.
- **Raid RPC** (хост меняет инвентарь, у всех реплицируется) — для перезарядки, снятия обвеса, плит.
- **Консоль разработчика** (`QuestHud`, `) — туда же команды оружия.

## 3. Данные

- `data/weapons.json` — калибры, модели-основы (точки крепления), оружие, патроны, магазины,
  обвес, пресеты, алиасы старых id.
- `data/armor.json` — жилеты/плитоносцы, плиты, шлемы, гарнитуры.
- `data/loadouts.json` — снаряжение ИИ по типам (мирные, мародёры, «Периметр»).
- `WeaponDb` (`src/combat/weapon_db.gd`) — типизированный доступ: `weapon(id)`, `ammo(id)`,
  `magazine(id)`, `attachment(id)`, `caliber(id)`, `preset(id)`, `mounts_of(entry)`, `fits(...)`.

### ID
Новые предметы: `wpn_hg_01…`, `ammo_545_std`, `mag_545_30`, `optic_lpvo_01`, `tac_flashlight_01`,
`muzzle_supp_545_01`, `grip_vertical_01`, `stock_tele_ak_01`, `carrier_perimeter_std`,
`plate_perimeter`, `helmet_perimeter_combat`, `headset_perimeter`. Код из ТЗ (HG_01, AR_06…) —
поле `code`. Старые id (`w_rifle`, `ammo_545`, `mod_red_dot`…) — в `aliases`: профиль при загрузке
переводится на новые, старые сохранения не ломаются. Новые id больше не меняются.

## 4. Экземпляр оружия

```
{"id": "wpn_ar_06", "n": 1, "dur": 91.0,
 "mods": {"optic_primary": {"id": "optic_lpvo_01"},
          "optic_offset":  {"id": "optic_offset_rd_01"},
          "side_left":     {"id": "tac_flashlight_01", "on": false},
          "side_right":    {"id": "tac_laser_01", "on": true},
          "muzzle":        {"id": "muzzle_supp_545_01"}},
 "mag": {"id": "mag_545_30", "ammo": "ammo_545_std", "rounds": 17},
 "sight": "primary"}
```
Магазин в рюкзаке: `{"id": "mag_545_30", "n": 1, "ammo": "ammo_545_ap", "rounds": 30}` (со
состоянием — не складывается). Плитоносец: `{"id": "carrier_perimeter_std", "dur": …,
"plates": {"front": {"id": "plate_perimeter", "dur": 17}, "back": {...}}}`. Шлем: `dur`, `mods`.

## 5. Крепления и совместимость

- У оружия — `mounts`: имя точки → `{"if": интерфейс}`. Имена точек общие:
  `optic_primary, optic_offset, side_left, side_right, underbarrel, muzzle, stock`.
  Магазин — отдельно: `mag_if` (интерфейс горловины).
- У обвеса — `fits`: список интерфейсов (`RAIL_TOP`, `RAIL_SIDE`, `RAIL_BOTTOM`, `SLIDE_RMR`,
  `OFFSET_45`, `THREAD_9`, `THREAD_545`, `THREAD_556`, `THREAD_762`, `THREAD_12`, `STOCK_AK`,
  `STOCK_AR`…). Новое оружие с тем же интерфейсом сразу принимает весь подходящий обвес.
- Конфликты: `blocks` у обвеса (например, длинная оптика 8× закрывает `optic_offset`) и
  `needs` (глушитель на стволе без резьбы — нельзя: интерфейса нет).
- **Угловой прицел.** Решение: точка `optic_offset` с интерфейсом `OFFSET_45` считается
  встроенным 45° кронштейном на верхней планке (упрощение из п.19 ТЗ). Формат `mods` допускает
  позже вложенный `{"id": кронштейн, "mods": {...}}` — физический адаптер.
- Позиции точек — в `weapons.json → models` (по процедурной основе), поправки — там же. Нет
  точки у модели — обвес ставится по запасной позиции, оружие не ломается.

## 6. Прицелы

- `sight` на экземпляре: `primary` / `offset`. Команда `toggle_sight` (O). Один прицел — ничего.
  Снят основной — используется угловой (или открытый).
- От первого лица: у каждого прицела своя линия прицеливания (`sight_h`, `ads_z`, крен). Угловой
  — модель в руках поворачивается на 45° по крену, линия углового прицела — на оси взгляда.
- В изометрии: основной оптический — медленнее довод, точнее, дальше, приближение камеры;
  угловой коллиматор — быстрый довод, лучше вблизи, без приближения.

## 7. Тактические устройства

- `side_left` / `side_right` (+ `underbarrel` для некоторых). Фонарь и ЛЦУ одновременно.
- Состояние `on` — на экземпляре обвеса (в записи оружия). T — фонари, L — ЛЦУ; у комбо
  `modes` → T и L включают свою часть независимо (OFF / свет / лазер / оба).
- Фонари из данных: `light: {range, angle, energy, indirect, specular}` — обычный и мощный.
- Свет у далёких ИИ гасится по расстоянию; фонарь в луче слепит (LightGlare, уже есть).

## 8. Урон и броня

- Пуля несёт `damage, pen, armor_dmg` (от патрона). Зоны: `head`, `thorax` (спереди/сзади —
  по направлению выстрела относительно корпуса), `arms`, `legs`.
- Плита защищает `thorax` своей стороны; шлем — `head`. Защита плиты = класс брони × состояние.
  Шанс пробития — плавная ступень `pen` против защиты. Не пробила — плита теряет прочность,
  человеку — тупая травма (`blunt`). Пробила — проходит часть урона, плита тоже изнашивается.
- Руки/ноги без плит (урон × множитель зоны). Голова без шлема или пробитый шлем — смерть (как было).
- Броня — не HP: жилет без плит почти не защищает.

## 9. ИИ

- Снаряжение ИИ — из `loadouts.json`: пресет оружия, магазины (реальные патроны), броня с плитами,
  шлем, гарнитура, аптечки. Стреляет своими магазинами: кончились — пистолет, потом отход.
- При смерти выпадает то, что было на нём: оружие с обвесом и износом, остаток патронов,
  магазины, броня с износом плит.
- Точность/поведение ИИ — прежние (баланс), урон — от патрона × `AI_DAMAGE_K`.

## 10. Прочность, вес, гарнитуры

- Прочность оружия 0–100: разброс, шанс задержки (редко на хорошем), цена. Износ за выстрел.
- Вес у каждого предмета; общий вес — штраф к скорости и выносливости выше порога.
- Гарнитура: тише свои выстрелы (шина Shots), громче шаги и тихие звуки (Steps / World),
  дальше слышно.

## 11. Порядок работ

1. Данные + WeaponDb + алиасы + WeaponStats от экземпляра (игра работает на новых данных).
2. Магазины и патроны (перезарядка сменой магазина, досыпка из россыпи), урон от патрона.
3. Крепления/интерфейсы, визуал по данным, конфликты.
4. Основной + угловой прицел, переключение (FPS + изометрия), HUD.
5. Фонарь / ЛЦУ / комбо, обычный и мощный фонарь.
6. Дульные, рукоятки, приклады — наполнение данных.
7. Прочность оружия, задержки.
8. Броня: плитоносцы, плиты, шлемы, зоны попадания, пробитие.
9. Гарнитуры.
10. Снаряжение ИИ, фракционный лут, реальный расход патронов.
11. Снятие обвеса и плит в рейде (с тела и из рюкзака).
12. Сохранение, миграция.
13. UI: карточка оружия, броня, патроны.
14. Команды разработчика.
15. Проверки (tools/arsenal_test).
