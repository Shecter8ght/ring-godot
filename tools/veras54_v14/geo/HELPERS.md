# ВЕРАС-54 v14: как писать модуль детали (памятка исполнителю)

Строим заново подробную high-poly модель автомата ВЕРАС-54 (по мотивам АК-12 образца 2018 года) для игры RING.
Только форма, без текстур. Прежняя версия v13 владельцу не нравится: «геометрия выглядит слишком кустарной, нужно
максимально приблизить к АК-12». Образец формы — модель Sketchfab «Kalashnikov AK-12» (RaduCarstean): её снимки
лежат в `_asset_src/veras54_v14_geo/refs`. Копируем **форму по снимкам**, сама чужая модель не скачивается.
Владелец принимает придирчиво: детализация предельная (заклёпки, винты, кнопки, оси, фаски, швы литья, насечки),
острых кромок нет (у каждой кромки скругление или фаска), примыкания деталей чистые, подвижные детали — отдельными
объектами с осью. Маркировка только вымышленная: «ВЕРАС-54», «5,45×39»; клейм «6П70», заводских знаков — нет.

## Способ
Детали — не булевы операции Blender, а **поля расстояний** на вокселях (numpy), сетку из поля делает OpenVDB.
Модуль `tools/veras54_v14/geo/sdf.py` — прочитай его целиком перед работой. Образец готового модуля здесь —
`part_receiver.py`; образцы побольше — модули пулемёта `tools/pkp/part_*.py` (тот же `sdf.py`, другие оси X):
`part_receiver.py` (штамповка, накладки, заклёпки, рукоятка), `part_grip.py` (рукоятка, скоба, крючок),
`part_stock.py`, `part_cover.py`, `part_barrel.py` (тела вращения, окна).

- Единицы — миллиметры. Оси: **+X к дулу, +Y влево стрелка, +Z вверх, −Y — правая сторона**. X = 0 — задний торец
  листа ствольной коробки, Z = 0 — ось канала ствола.
- `F = Field(имя, lo, hi, h)` — габариты поля с запасом ≥ 1 мм вокруг тела. `F.add(тело, r, bbox=…)` — объединение
  с галтелью r; `F.sub(тело, r, bbox=…)` — вырез со скруглением кромки r; `F.apply(тело, "inter", r)` — пересечение;
  `F.displace(fn, bbox, fine=False)` — рельеф смещением поверхности; `F.shell(t)` — превратить тело в лист
  толщиной t (рельеф повторяется с изнанки — так делается штамповка).
- Тела: `box`, `box_e` (свои радиусы по осям), `cyl`, `cone`, `sphere`, `capsule`, `torus`, `plane`, `half`,
  `prism(Poly(fillet_poly(точки, радиусы)), "XZ", w0, w1, rim=…)` — контур × выдавливание со скруглёнными
  кромками, `prism2(плоская фигура…)`, `rect2 / circle2 / seg2 / union2 / minus2`, `revolve(Poly, "X", центр)`,
  `strip(Path2(fillet_path(…)), "XZ", толщина, w0, w1, rim)` — гнутая полоса, `wire(точки, r)` — проволока,
  `rot / move / both / union / inter / minus`. Надписи — `text2` + `engrave` (шрифт — `dims.font_path()`).
- Готовые сетки (вместо поля): `lathe_mesh(профиль, seg, axis, c, closed, mats)` — тело вращения (трубки, оси),
  `helix_mesh` — витая пружина, `tube_mesh`, `join_meshes`. Функция детали тогда возвращает кортеж сетки.
- Функции тел получают массивы `X (nx,1,1)`, `Y (1,ny,1)`, `Z (1,1,nz)` — только операции numpy с вещанием.
  Свою форму (переменная ширина, сужение, выпуклый бок рукоятки) пиши своей функцией `f(X, Y, Z)` из `u_round`,
  `i_round`, `smoothstep` — как `leaves` в `tools/pkp/part_receiver.py`.

## Грабли
- **Всегда давай `bbox`** местным операциям (`dims.bb(x0, x1, y0, y1, z0, z1)`): без него операция считается по
  всему полю. Деталь должна считаться секунды.
- Объединение с галтелью двух тел с общей плоской гранью вспучивает грань на 0,29·r; пересечение с совпадающей
  плоскостью усаживает. Стыки делай на плоскости (плоские фигуры `union2` → `prism2`), обрезаемое строй длиннее
  плоскости обреза, после галтели подрезай плоскость обратно (`F.apply(half(…), "inter", 0)`).
- Лист и тонкие стенки — не тоньше 4 вокселей при черновом расчёте (шаг черновика = 2·h из `parts()`).
  Шаг h: мелкие детали 0,06–0,1; средние 0,1–0,13; крупные (приклад, цевьё) 0,15–0,2.
- Скругление `rim` у `prism` меньше половины толщины выдавливания и меньше радиуса углов контура.
- Соседние детали не должны пересекаться: зазор 0,1–0,3 мм; посадки (ось в отверстии) — отверстие на 0,05–0,1 больше.
- Длинный heredoc с кириллицей в Bash падает — файлы пиши инструментом Write, скрипты запускай из файла.
- Python пишет CRLF — при записи файлов кодом указывай `newline="\n"`, кодировка UTF-8.
- На диск C: ничего не пиши (он полон): временное — в `_asset_src/veras54_v14_geo/trace/<твоя метка>`.

## Каталог деталей модуля
```python
def parts():
    return [
        dict(name="Selector_Lever", build=selector, h=0.08, coll="Органы управления", mat="Steel_blued",
             pivot=[x, y, z],            # точка шарнира в мм — начало координат объекта
             motion="поворот вокруг Y: 0 — «АВ», −10° — предохранитель, +9° — «ОД»",   # для рига, словами
             adapt=0.06),                # необязательно: укрупнение граней в плоских местах
    ]
```
`mat` — из `assemble.MATS` (Steel_blued, Steel_phosphate, Steel_bare, Spring_steel, Alu_anodized, Polymer,
Mag_polymer, Rubber, Case_lacquer, Bullet_jacket). `parent="Имя"` — деталь едет за другой. Имена объектов —
английские, `Часть_Подчасть`; имена коллекций — русские.

## Размеры, образец и что нельзя сдвигать
- Общие размеры — `tools/veras54_v14/geo/dims.py` (только читать; бери имена оттуда, чисел не переписывай). Свои
  размеры детали — константами в начале своего модуля, у каждой комментарий, с какого снимка она снята, или «оценка».
- **Места, от которых зависят хваты рук в клипах (владелец: «без нужды не сдвигать»)**: пистолетная рукоятка, шахта
  и магазин, рукоятка затворной рамы (`CH_X`, `CH_Z`, `CH_TIP_Y`), переводчик (`SELECTOR_AXIS`), цевьё, ось спуска.
  Форма — по образцу, место — как у v13 (перечень объектов v13 с габаритами в мм:
  `_asset_src/veras54_v14_geo/work/v13_objects.txt`). Длины впереди коробки (цевьё, газовый узел, ствол) — v13.
  **Ширины — по образцу** (настоящие: коробка 33 мм; у v13 всё было в полтора раза шире — это и исправляем).
- Снимки образца: `refs/tiles` — «плитки» почти ортогональной камерой: `R_…` правый бок, `L_…` левый, `T_…` сверху,
  `U_…` снизу, `B_…` сзади, `F_…` спереди (в имени — центр кадра в метрах образца и угол зрения);
  `refs/sketchfab` — обзорные виды и ракурсы 3/4 (`P01…P16`, `Q01…Q04`), камеры — `refs/views.json`.
  Картинки смотри инструментом Read. Браузер не трогай (он общий, им пользуется главная сессия).
- **Миллиметры с плиток**: `python -X utf8 tools/veras54_v14/geo/ref_tiles.py <плитка.jpg> <выход.png> [u0 v0 u1 v1]
  [--zoom 3] [--step 5] [--depth D]` — плитка (или её кусок u0 v0 u1 v1 в мм) с сеткой в мм осей ВЕРАС.
  Оси кадра: бок — (X, Z), сверху / снизу — (X, Y), торцы — (Y, Z). `--depth` — на сколько мм плоскость детали
  ближе к камере, чем плоскость кадра: бок — |Y| детали (борт коробки 16,5); сверху — Z детали минус 20,5;
  снизу — −79,5 минус Z детали; торцы — расстояние от X = 252 в сторону камеры. Без поправки ошибка — 0,3 % на
  каждые 18 мм глубины. Куски складывай в `_asset_src/veras54_v14_geo/trace/<твоя метка>`.
- У образца перед оружия на 33 мм короче заводского, а труба приклада и приклад стоят по образцу — если место по
  образцу и по v13 расходится больше чем на 2 мм и это не оговорено в `dims.py`, напиши об этом в отчёте.
- Фото настоящего АК-12 (6П70) — `E:\Models Blender\WEAPONS\ВЕРАС-54 — модель и обвесы\ВЕРАС-54\Актуальное\

## Запуск и проверка
```
VERAS_TAG=<твоя метка> bash tools/veras54_v14/geo/go.sh 2 "<модули>" "<виды>"
```
`<модули>` — короткие имена модулей через пробел (`receiver`, `grip controls`); один раз посчитай с коробкой
(`"receiver <свой>"`), дальше пересчитывай только свой модуль — остальное в твоей папке сохраняется. Чужие модули
не собирай (они в работе и могут не читаться). Детали, перенесённые из v13 без изменений (ствол, газовый узел,
дульное устройство, затвор, целик, патроны — `transfer.py`), добавляются сами.
Результат: `_asset_src/veras54_v14_geo/work/v14_k2_<метка>.blend`, кадры `work/shots_k2_<метка>`, листы сверки
`work/cmp_k2_<метка>` (образец | наш кадр | наложение: образец красным, наш голубым).
Виды — через запятую: имя из `refs/views.json` (`R02_receiver_right`, `P05_grip_front_right` …), имя плитки без
`.jpg` (`R_x-0.21_z0.17_f1.0`) — кадр той же камерой ложится на снимок образца; или свой:
`имя:x:y:z:куда_x:куда_y:куда_z:угол` (мм ВЕРАС, угол зрения в градусах; для крупного плана — 6000 мм и 0,5–1°).
Увеличить лист: `python -X utf8 tools/veras54_v14/geo/compare.py <shots> <вывод> <вид> --crop x0 y0 x1 y1 --zoom 3`
(пиксели кадра 800 × 635). Чистовой шаг вокселя — `go.sh 1 …` (в 8 раз дольше) — в конце, для проверки мелочей.
Пересечения деталей: `"D:/ПРОГРАММЫ/Blender 5/blender.exe" -b <твой .blend> --python tools/veras54_v14/geo/check_overlaps.py`
— по твоим деталям должно быть пусто (посадки «ось в отверстии» назови в отчёте — их внесут в список разрешённых);
сетки и габариты — то же с `measure.py` (`MESH_PROBLEM` быть не должно).
Каждый кадр смотри сам (Read): форма, кромки, примыкания, пересечения с соседями. Правь, пока наложение
не сойдётся в 1–2 пикселя, а крупные планы не станут чистыми и похожими на образец **со всех сторон**
(оба бока, сверху, снизу, торцы, 3/4).

## Правила
- Правь **только свой файл модуля** `part_<имя>.py`. `sdf.py`, `dims.py`, `build.py`, `assemble.py`, `shots.py`,
  чужие `part_*.py` не трогай: нужна новая функция или общий размер — определи в своём модуле и скажи в отчёте.
- Комментарии по-русски, о смысле (зачем), а не о синтаксисе; имена по-английски.
- Ничего не коммить в git. Не трогай чужие процессы Blender и Python. `VERAS_JOBS` не поднимай выше 3.
- В конце — отчёт (до 50 строк): какие детали сделаны; для каждой подвижной — точка шарнира, ось или направление,
  ход или угол (для рига); какие размеры оценочные; где наложение не сошлось и на сколько; расхождения с v13
  в местах хвата; что не сделано.
