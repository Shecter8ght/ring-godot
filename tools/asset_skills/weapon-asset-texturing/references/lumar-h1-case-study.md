# ЛУМАР H1 — история требований, итераций и исправлений

Записано 2026-10-07. Это история авторинга конкретного прицела и основания правил навыка. Промежуточные неудачные решения приведены с исправлениями, а не как рецепты. Цель — повторить метод на других игровых оружейных ассетах, сохраняя их материалы, геометрию и контекст использования.

В пакет включено [сравнение трёх финальных состояний](images/lumar-h1-conditions.jpg). Это результат v9 для просмотра, не эталон внешнего вида любого оружия и не свидетельство одобрения текстур владельцем.

## Задание и последовательность

1. Владелец попросил взять последнюю согласованную геометрию коллиматора в библиотеке ВЕРАС-54 и довести текстуры до четырёх присланных видов: царапины, истёртость, сошедшая краска, допускаются сколы. Референсы показывали матовый тёмный корпус с микрозерном, разорванные светлые кромки, риски и локальный износ кнопок/крышек/крепления.
2. Найдены согласованная геометрия v6 и последний текстурный исходник v7. Их форма сопоставлена. v7 уже имел исходные слои UCUPaint; новую работу делали поверх с сохранением исходника.
3. Подготовлена v8 с усиленной кромкой, сколами, царапинами, собственными картами высоты/NormalGL и зерном покрытия. Старые слишком слабые/конфликтующие слои износа отключены, полезная база сохранена.
4. Владелец счёл результат промежуточным. Он пояснил историю предмета: «снимают и ставят обратно», «отвёртками подкручивают», нажимают грязными пальцами; оседает пыль, остаются масляные пятнышки, грязь попадает в труднодоступные щели. Попросил раздобыть отпечатки пальцев и оголить светлый отражающий металл на грани.
5. Возник вопрос: должно ли стекло быть прозрачным с обеих сторон, если обратная сторона выглядит непрозрачной. Проверили материал и оба направления на контрастном фоне, затем улучшили читаемость прозрачного окна.
6. Дополнительно запрошены три экземпляра для будущей игры: идеальный, 60% нормальности / 40% износа, 20% нормальности / 80% износа. У последнего стекло должно быть треснутым. Разная стоимость и вероятность лута обозначены как будущая задача.
7. Подготовлена v9: три самостоятельных редактируемых high-poly `.blend`, пять нативных стеков UCUPaint, карты/лицензии и галерея. Проверены файлы именно из выдачи. Игровые параметры и импорт не выполнялись. Согласование геометрии v6 сохраняется; последующего одобрения текстур v9 владельцем эта история не утверждает.
8. Владелец попросил упаковать историю и все правки в повторно применимый скилл; текущий пакет содержит процедуру, технические уроки, этот разбор и узкие помощники.

## v8: покрытие и повреждения

Исходные стеки v7 имели 18 слоёв. В v8 добавлено девять собственных слоёв (27 всего); старые слабые слои 08–11 отключены, раннее старение/масло ослаблены.

| 28 | Собственный tangent NormalGL |

Созданы 4K-маски с отсечением по UV-островам. Истинные выпуклые рёбра выделялись по геометрии; согласованное направление штампа требовало одинаковой сортировки концов ребра. Короткие криволинейные сегменты сначала создавали регулярные зубцы: уменьшены вероятность/размер штампа на таких участках. Износ уплотнений уменьшен, чтобы резина не читалась как металлическая ободранная кромка.

Сначала фон высоты был 255; заменён на нейтраль около 128/0.5 и согласованный OVERLAY. Enum ADD оказался недоступным. Микрозерно порядка 10–15 мкм, глубина повреждений примерно 16–80 мкм по основанию; сила собственного NormalGL примерно 0.33–0.52. Эти значения описывают этот маленький прицел.

Первый оголённый металл был слишком серым/матовым. В итоге светлая выбранная грань получила линейный RGB около (0.62, 0.655, 0.69), Metallic=1, Roughness=0.20. Вторичные сколы — около (0.38, 0.405, 0.43), 0.98/0.32; загрязнённая широкая потёртость — около (0.23, 0.245, 0.26), 0.90/0.43. Различия нужны для читаемости контактов, не для назначения этих чисел любой стали или пластику.

Из официального ambientCG получены [Fingerprints003 4K-PNG](https://ambientcg.com/view?id=Fingerprints003) с [CC0](https://docs.ambientcg.com/license/). Источник `Fingerprints003_4K-PNG_Opacity.png` сохранён. Это процедурный рисунок, не гарантированное фото реального пальца. Из атласа выделен узнаваемый отдельный отпечаток. Физические штампы 10–21 мм проецировались на поверхности корпуса/крышки/кнопок через треугольники и UV, а не клеились как плоская наклейка поверх всего объекта. AO сам по себе давал недостаточно читаемой грязи. Добавлены физически размещённые маски контактов и карманов. Первое синусоидальное поле создало заметную гребёнку; заменено на воспроизводимый непериодический интерполированный hash/value noise. Регулярная охристая пыль выглядела нарисованным ободком: оттенок приглушён до серой минеральной пыли, края отложений прерваны локальной нерегулярностью.

Первый штамп светлой грани не учитывал наклон задней кромки: почти не появлялся. Проекция перенесена на фактический наклон; покрытие маски выросло с примерно 2648 до 45900 пикселей, после чего длинная отражающая грань стала видимой. Формула с координатами ЛУМАР не переносится на другие модели; переносится проверка истинной поверхности.

### Почему включённые слои сначала не работали

Helper добавлял NOISE и отдельный MODIFIER/RAMP следом. Ramp применялся к уже накопленному Image × Noise либо AO, отсекая слабые пиксели целиком. Отчёт о включённых слоях выглядел успешным; рендер показывал слишком мало пыли и контактного износа.

Исправление: перенести порог внутрь модификаторов самой NOISE-маски, отключить старый накопленный Range, переподключить слой/корень. Точный API и помощник находятся в [справке UCUPaint](ucupaint-api.md). Это ключевая техническая правка истории.

После неё обнаружился другой дефект: ToolWear рисовал полосатую «ёлочку» по всем головкам винтов/регулировкам. На группе 09 маска IMAGE отключена; заменена EDGE_DETECT радиусом около 0.00018 м × атрибут `V9ToolContact` только для нужных деталей × локальный Noise. Интенсивность — около 0.62 тяжёлого / 0.40 среднего. На алюминиевом креплении слишком сильные установочные полосы ослаблены до 0.27/0.17. Исправление одного графа потребовало повторного осмотра всего проявившегося эффекта.

Средний вариант ограничен по площади очагов, а не просто всем слоям задана половина интенсивности. Новый отключает эксплуатационные слои, сохраняя заводскую основу. Тяжёлый получил широкие потери покрытия, больше загрязнения и повреждённое стекло.

## Стекло и трещина

Исходная объёмная сетка стекла имела 296 faces, одобренные bevel/weighted normal, Transmission=1, Metallic=0, IOR=1.45; базовый цвет около (0.638, 0.869, 0.838), Roughness=0.08, coat=0.15. Односторонняя непрозрачная ветвь не найдена. Тёмный фон/отражение делали вид сзади непрозрачным на глаз.

Для читаемости окна сделаны слабее оттенок (около 0.88, 0.96, 0.93), Roughness=0.018, coat=0.025, сохранены Transmission=1 и IOR. В Cycles обеспечены достаточные отражения/трансмиссия (max bounces 16, transmission 12). Это художественная настройка, не измерение оптической системы.

Новая нормализованная Y/Z-развёртка LensUV совмещает трещину двух поверхностей. Только у 20% состояния включены: слой 40 — белёсое локальное рассеяние по собственному ветвящемуся рисунку; 41 — Bump порядка 65 мкм; 42 — слабое загрязнение границы окна. Стекло между линиями остаётся прозрачным, сетка не разрушена.

С временной сине-жёлтой шахматной подложкой получены четыре вида: целое и треснутое окно с обеих сторон. Подложка не сохранялась в модели. Проверены первичные объяснения Aimpoint об уходе и наклонной передней линзе; их конструкция не приписывалась ЛУМАР. Ретикл сохранён как исходная художественная геометрия/свечение, физическая коллимация не моделировалась.

## Дополнительные ошибки и окончательные исправления

| Ошибка/риск | Исправление и практический урок |
|---|---|
| Несуществующий ADD у height | Читать установленный enum; использован допустимый OVERLAY |
| `U.bl_info` в расширении отсутствует | Версию читать через `U.common.get_current_version_str()` |
| RGB свойства и RGBA фактического входа не совпадают размерностью | Проверять первые три компонента цвета, синхронизировать через API |
| RNA меняется, group input остаётся старым | `set_entity_prop_value`, затем `get_entity_prop_value` и проверка |
| Присваивание имени изображения в `source` | Учитывать, что поле может хранить имя узла; неверная попытка удалена |
| `Principled.inputs['Weight']` дал KeyError | Не полагаться на напечатанные метки как на ключи сокетов |
| Начат build до завершения генератора карт | Дождаться процесса и карты; ошибка BroadWear исправлена пересборкой |
| Python-ошибка могла оставить exit code 0 | Добавлен `--python-exit-code 1`, проверка маркера завершения |
| Непишущийся OptiX-кеш замедлял рендер | Task-local OPTIX/CUDA cache, без правки глобальных preferences |
| Разные поколения packed-карт имели один basename | Уникальные экспортные имена с версией/digest, mapping и hash |
| Грязь была слишком равномерной/бежевой | Приглушённый оттенок, нерегулярные отложения по контактам |
| Красивая промежуточная картинка после правки графа больше не актуальна | Пересохранить и перерендерить фактический конечный файл |

История не подменяет этот результат старым PASS; модели в ходе изготовления навыка не пересохранялись.

При использовании навыка для другого оружия переносить нужно причинную карту износа, нативную редактируемость, корректные области масок, физический масштаб и проверку сохранённого результата. ЛУМАР-специфические координаты, численные пресеты, количество слоёв и три процента не обязательны.
