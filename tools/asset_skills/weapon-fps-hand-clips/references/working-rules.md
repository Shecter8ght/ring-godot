# Общие правила работы с ассетами

## Интернет и доказательства

Владелец разрешает нейросети самостоятельно выходить в интернет для поиска референсов, фотографий, размеров, материалов, документации Blender/UCUPaint/Godot и лицензированных ресурсов, необходимых для задания. Используй доступный поиск, браузер, коннектор или загрузку файлов. Повторно спрашивать разрешение на обычный поиск и скачивание подходящих бесплатных ресурсов не нужно. Разрешение пользователя не отменяет ограничения инструментов и среды; при отказе сообщи конкретную причину.

Предпочитай первичные источники: производителя, музей/каталог предметов, официальную документацию и исходную страницу библиотеки материалов. Записывай ссылку, точный вариант предмета и подтверждённые размеры. Не смешивай модификации по похожим фотографиям. Для скачанных карт/моделей сохраняй источник, лицензию, оригинал и преобразования; изображения с неизвестными правами используй как визуальные референсы, не выдавай за свои текстурные карты. Поиск не даёт разрешения покупать ресурсы или публиковать работу.

## Неясности: вопросы вместо выдумывания

Если непонятна развилка или отсутствуют данные, не додумывай решение за пользователя. Сначала проверь доступные файлы, предыдущие сообщения и надёжные источники. Если после этого неясность остаётся, перечисли конкретно, что нужно решить, и попроси пользователя дать решение, скриншот, фотографию, изображение, размеры или нужный ракурс.

Вопрос должен называть предмет и участок, объяснять влияние выбора и предлагать 2–3 понятных варианта, если они известны. Пример: «На фото не видно крепление задней части. Пришли вид сзади или выбери: отдельная пластина / цельное продолжение корпуса». Если просишь файл, используй способ общения, который поддерживает вложения; текстовый опрос не заменяет загрузку изображения.

Не выдавай предположение о форме, материале, неизвестной стороне предмета, скрытом узле, маркировке, варианте износа или художественном стиле за подтверждённое решение. Отсутствие ответа не является согласием. Приостанови зависимую часть, продолжая независимые работы с уже известными данными. Если неясность блокирует всё задание, сохрани результат и сформулируй один собранный запрос. Не спрашивай повторно о решениях, уже принятых пользователем. Технический метод можно выбирать самостоятельно, когда исходные данные и желаемый результат определены.

## Источник и сохранение

Найди актуальный ассет и его принятые версии. Если живой Blender имеет несохранённые правки, сохрани отдельную копию через доступный инструмент; если доступа нет, попроси пользователя сохранить и передать актуальный файл, не утверждай, что видишь открытое окно. Фоновая правка .blend не обновляет открытую сцену.

Связывай принятие формы с конкретным сохранённым кандидатом; при длительной работе используй контрольную копию и её SHA-256. Не заменяй её самым свежим пересохранённым файлом автоматически. Перед существенной правкой сохрани рабочую копию для отката до проверки новой выдачи.

**Моделирование и текстурирование — замена файлов после каждой правки (владелец, 2026-11-11).** Повторно открой новый файл из папки выдачи, проверь его и зависимости, затем при передаче владельцу окончательно удали заменённые файлы той же модели или того же текстурного проекта и их устаревшие резервные копии. Удаляй конкретные файлы по проверенным путям, без переноса в корзину, архив или карантин. Сохраняй актуальный редактируемый файл, нужные зависимости и самостоятельные варианты. После принятия high-poly сохрани последнюю принятую редактируемую модель как исходник для будущих правок. При выдаче текстур или игровых производных этот исходник сохраняется. Если владелец снова поручил правку high-poly, новая геометрия заменяет принятый исходник после принятия обновлённой формы.

Веди один компактный asset-state.md внутри папки ассета: источник/согласование, вариант, размеры/оси, текущая стадия, состояния, контролы, зависимости, источники и оставшиеся вопросы. Не создавай отдельный журнал на каждый скол. Указывай актуальные пути выдачи и принятого исходника. Следи за свободным местом до большого набора 8K-карт, packed-копий и запеканий. Временные резервные копии используй для восстановления в ходе текущей правки.

По просьбе остановиться или по заданному сроку сохрани достигнутый результат и прекрати свои новые задачи/рендеры. Не закрывай чужие несохранённые окна и не останавливай чужие процессы. Выключение ПК выполняй только по отдельному поручению владельца.

## Доступные инструменты и переносимость

Инструкции одинаково применимы в Codex и Claude Code. Выбирай реально доступные инструменты, не называй отсутствующий MCP выполненным действием. Для живого Blender предпочтителен подключённый коннектор; для сохранённого кандидата допустим фоновый Blender с Python. bpy-скрипты запускаются Python самого Blender. Скрипты обработки изображений могут использовать отдельный Python с установленными Pillow/numpy.

Не сохраняй глобальные preferences Blender ради задачи. На Windows сохраняй русский текст в UTF-8, внешние Python-утилиты запускай с -X utf8. Используй --python-exit-code 1, проверяй код выхода и наличие завершённого файла. Вспомогательные фоновые процессы не должны открывать лишние окна. Показывай готовый ассет в видимом приложении, когда это помогает просмотру и разрешено заданием.

Для проекта RING сначала прочитай AGENTS.md или CLAUDE.md, docs/OWNER_NOTES.md, конец docs/STATUS.md и актуальный backlog. Правила проекта определяют пути, Git и внедрение. Скилл моделирования или текстурирования не даёт сам по себе разрешения на импорт в игру. Подготовку и интеграцию выполняет отдельный запрос и godot-asset-preparation.
