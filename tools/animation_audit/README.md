# RING — аудит FBX-анимаций

Папка `assets/animations` сканируется только на чтение. Никакие исходные FBX не перемещаются и не изменяются.

## Запуск

Из корня проекта:

```powershell
python tools/animation_audit/audit.py
python tools/animation_audit/serve.py
```

Откройте <http://127.0.0.1:8765>. Для просмотра достаточно локального сервера: версия Three.js 0.180.0 лежит в `viewer/vendor` и не требует сети. Лицензия библиотеки — `viewer/vendor/LICENSE`.

Выберите состояние слева. Загружаются только его кандидаты, одновременно не более четырёх. Для пятого кандидата используйте меню «Ещё кандидаты». Кнопки SELECT, MAYBE и REJECT сохраняют решение в localStorage. «Экспорт выбора» создаёт `selection.json` и `SELECTION.md` рядом с этим файлом. Отмена решения — повторное нажатие той же кнопки. Ни один выбор не считается финальным, пока вы сами его не отметите.

При смене состояния просмотрщик освобождает WebGL-контексты, геометрию, материалы и текстуры. FBX без меша показываются как анимированные скелеты. Решение о тактической реалистичности следует принимать по движению; имена служат только для предварительного отбора.

## Файлы

- `all_animations.json` — все FBX, размеры, хэши, классификация, версия формата.
- `exact_duplicates.json`, `semantic_groups.json` — точные и возможные смысловые дубли.
- `packs.json`, `coverage.json`, `shortlist.json` — наборы, пробелы и предварительный список.
- `rig_probe.json` — выборочная проверка Blender: Persona.blend и по одному FBX из каждого набора.
- `REPORT.md` — сводка и технические ограничения.
- `viewer/shortlist.json` — данные только для браузерного просмотрщика.

Весь анализ по названиям может содержать неточности. Ретаргетинг и подключение к Godot этим инструментом не выполняются.
